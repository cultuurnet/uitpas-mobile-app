# AGENTS.md

UiTPAS mobile app: Expo (SDK 57, Continuous Native Generation) + React Native, TypeScript. Single package, no monorepo.

## Git workflow
- **Never commit or push unless explicitly told to.** Make the edits, leave them uncommitted, and report the changed files.
- When a commit message is wanted, suggest a short Conventional Commit (`feat: …`, `fix: …`, `chore: …`): one line, nothing to prove beyond the change itself.

## Toolchain
- Use **pnpm** (`packageManager: pnpm@10.23.0`, `pnpm-lock.yaml`).
- Node 24 is pinned in `.nvmrc`, which is what CI reads; `.node-version` matches it.
- `android/` and `ios/` are gitignored and generated by `pnpm prebuild` (`expo prebuild --clean`). Never edit native files by hand. Change `app.config.ts`, the config plugins, or `expo-build-properties` instead.
- `@sentry/react-native` is excluded from `expo install` (`package.json` → `expo.install.exclude`), so bump it manually. Metro uses `getSentryExpoConfig`.

## Verification (what CI runs on PRs)
- `pnpm lint` then `pnpm check-types`. There is **no test suite**, so these two commands are the whole gate.
- If you change `pnpm-lock.yaml`, CI also runs `pnpm dlx expo-doctor`. Run it locally after any dependency change.
- Prettier only formats `src/**` (`pnpm format`). ESLint runs Prettier as a plugin.

## Lint rules that will bite
- Object keys, JSX props, interface members, and string enums must be **alphabetically sorted** (`sort-keys-fix`, `react/jsx-sort-props`, `typescript-sort-keys`). Run `pnpm lint --fix`.
- Import groups (`simple-import-sort`): `react*` and other packages, then absolute imports, then relative imports.
- Import `styled-components/native`, never `styled-components`. `no-console` is an error, so use `src/_utils/logger.ts`.
- `tsconfig` has `strict: false` and `strictNullChecks: false`. Don't "fix" the nullability types across the codebase.

## Env / config
- Config comes from `.env` (see `.env.example`). Only `EXPO_PUBLIC_*` vars are used. They pass through `app.config.ts` → `extra` and are read via `Config` in `src/_config/env.ts`. A new variable needs all three places, plus the `.env` steps in the `release-*.yml` workflows.
- `EXPO_PUBLIC_NODE_ENV` must be set: `src/_config/environments.ts` calls `.toLocaleLowerCase()` on it. It resolves to `beta` or `production`; any other value counts as `production`.

## Code layout (`src/`)
- Gold standards (based on `src/shopDetail`) live in `.ai/gold-standard/`. Read the relevant file before scaffolding a screen, component, query hook, model, or route.
- Folders with a `_` prefix are shared: `_components` (barrel `index.ts`), `_hooks`, `_http`, `_config`, `_context`, `_routing`, `_translations`, `_styles`, `_utils`. The other folders are one feature per screen. Each feature has its own `_queries/`, `_models/`, `_components/`, and `style.ts`.
- API calls go through `usePubliqApi()` (`src/_hooks/usePubliqApi.ts`). It wraps TanStack Query and sets the bearer token. Pass `'uitdatabank'` as the host for unauthenticated UiTdatabank calls. Put one `useGetX` hook per file in the feature's `_queries/`.
- Routes and their param types live in `src/_routing/_components/` (`RootStackNavigator`, `MainNavigator`, `TRootStackParamList.ts`).
- All UI strings go through i18next. Dutch only: `src/_translations/locales/nl.json`, with UPPER_SNAKE nested keys.
- Icons are PNGs at @1x/@2x/@3x, registered in `src/_assets/icons/index.ts` and rendered with `<Icon name=... />`.
- Styling uses `styled-components/native` with the theme in `src/_styles/theme.ts`.

## Branching / release
- Feature branches (`feature/*`, `bugfix/*`) target `develop`. `main` is production.
- To create a release, run the "Create new version" workflow (`version.yaml`). It opens a `release/<version>` PR against `develop` (beta) or `main` (prod). Merging a `release/*` PR triggers the fastlane builds in `release-beta-app.yml` / `release-prod-app.yml`. Don't bump `package.json` versions by hand.
- **Never edit `versions.json`.** It sets the app's min and target versions for the force-update screen (`src/update`), so changing them is an operational/release decision, not a code change. Jenkins (`Jenkinsfile`, `Rakefile`, `lib/tasks`) only lints that file and uploads it to S3. It does not build the app.
