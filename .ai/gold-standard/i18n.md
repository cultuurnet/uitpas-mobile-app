# i18n (Dutch-only translations)

Source of truth: `src/_translations/i18n.ts`, `src/_translations/locales/nl.json`; consumers: every screen/component via `useTranslation`.

## Setup (fixed)

- `i18n.ts` inits i18next with `resources: { nl: { translation: NL } }`, `fallbackLng: 'nl'`, `interpolation.escapeValue: false`, language from `react-native-localize`. No `compatibilityJSON` — that option was removed in i18next 27; plurals use the v4 JSON format (see key rules). Dutch only — no other locale files exist.

## Key structure (`nl.json`)

```json
{
  "NAVIGATION": { "SHOP": "Voordelen" },
  "SHOP": {
    "HEADER_TITLE": "Shop",
    "SHOW_MORE": "Toon meer",
    "SECTIONS": { "ONLINE": "Online", "CITY": "Voordelen in {{city}}" }
  },
  "SHOP_DETAIL": {
    "HEADER_TITLE": "Voordeel",
    "SHOW_MORE": "Toon {{count}} andere locatie",
    "SHOW_MORE_other": "Toon {{count}} andere locaties",
    "REDEEM": { "MODAL_TITLE": "Voordeel omruilen" }
  },
  "PERIODS": { "DAY": "dag" },
  "ERROR": { "ORGANIZER_ADDRESS": "..." }
}
```

## Key rules

- **UPPER_SNAKE nested keys**, top level = feature name (`SHOP`, `SHOP_DETAIL`, `PROFILE`), nested per screen area (`SHOP.SEARCH.FILTERS.SORT.TITLE`, `SHOP_DETAIL.WHO_CAN_REDEEM.UNREDEEMABLE_MODAL_TITLE`). One shared top namespace `SHARED`/`ERROR`/`NAVIGATION`/`PERIODS` for cross-feature strings.
- **Interpolation** `{{name}}`; **plural** via the i18next v4 JSON format: the base key holds the singular form and a `_other` sibling holds the plural (`POINTS` / `POINTS_other`); `_one` is optional because the base key is the fallback when count is 1. Never use `_plural` — i18next 27 ignores it silently. **inline markup** via `<bold>`, `<button>` tags consumed by the shared `Trans` component (`bottomSpacing`, `size`, `selectable`, `values`, `parent` props).
- **In React components**: `const { t } = useTranslation()` then `t('SHOP_DETAIL.REDEEM.BUTTON')` with `values` for interpolation; keys sometimes built dynamically — `` t(`PERIODS.${redeemConstraint.period}`) `` (allowed; enum values must match keys).
- **Outside React** (navigators, helpers): `import { t } from 'i18next'` and call directly — `i18n.t('SHOP_DETAIL.HEADER_TITLE')` in `RootStackNavigator`.
- **Error strings from API**: `TApiError.endUserMessage?.nl` rendered raw; only app-side fallbacks go through `t(...GENERIC_ERROR)`.
- Keys referenced by constant arrays (`SECTIONS`, `SEARCH_TERMS`, `CATEGORIES`) store the **key**, not the translated string; translate at render time with `t(title)`.
- Adding a key: nl.json only, in the feature's namespace, alphabetically sensible position near siblings; never hardcode Dutch strings in components (ESLint won't catch it — review discipline).
